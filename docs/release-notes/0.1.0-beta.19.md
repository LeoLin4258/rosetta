# Rosetta 0.1.0-beta.19

Rosetta beta.19 focuses on the new PDF v2 translation path, faster long-PDF
local runs, and clearer repair guidance when Windows blocks Rosetta's local
runtime connection.

## Highlights

- PDF translation now uses Rosetta's v2 PDF engine contract. The PDF component
  prepares layout and renders pages, while Rosetta owns local translation,
  page validation, and commit decisions.
- The updated PDF component packs are now the default on Windows x64 and macOS
  Apple Silicon. Older beta PDF page artifacts are reset and should be
  regenerated through the new v2 path.
- Long PDF translation on the Windows Lightning runtime now batches text across
  pages and reuses collected layout during replay, reducing repeated local
  model calls and avoiding unnecessary second-pass layout work.
- PDF page artifacts are written quickly during translation and compressed in a
  background maintenance task, keeping translated pages responsive without
  permanently growing the job cache.
- PDF progress now counts translated characters from pages that actually commit,
  so the status bar reflects accepted page results rather than raw provider
  output.
- PDF preview raster sizing is more consistent with the source page dimensions,
  improving side-by-side preview alignment.
- Windows managed runtime failures now include local loopback diagnostics.
  When Rosetta detects the common Public-network case, onboarding and Settings
  can offer a guided repair and retry path instead of leaving users at a generic
  startup failure.
- Windows PDF background compression no longer flashes a console window while
  it works.

## Supported platforms

- Windows 10/11 x64. The recommended managed runtime uses llama.cpp Vulkan on
  supported AMD, Intel, and NVIDIA GPUs. Machines without a compatible Vulkan
  path may use CPU fallback or an explicitly configured external API.
- macOS 13 or newer on Apple Silicon remains supported through the existing
  local macOS runtime.

Unsigned Windows Preview installers may show a SmartScreen or
unknown-publisher warning on first install unless an Authenticode certificate
is configured during release.

Rosetta remains local-first. Documents, translations, job caches, prompts, and
runtime logs are not uploaded by the release or update system.
